# Fitzone — опис проєкту

## Що це

Fitzone — фітнес-клуб (район "Лівобережний", судячи зі старих URL типу
`gym-levoberegniy`). Офіційний сайт зараз на Wix (`fitzone.com.ua`).
Проєкт — повне переписування сайту на власний стек (Python + Flask),
з переходом на власну БД, адмінку і (де потрібно) власне API замість
Wix CMS / Velo-коду.

## Навіщо переписуємо

- Позбутись обмежень Wix-конструктора та Velo-коду
- Отримати повний контроль над даними (тренери, прайс, розклад, школа
  інструктора) через власну БД та адмінку
- Прибрати ручні "перехідні" таблиці відповідності назв (зараз частина
  назв абонементів з API виводиться некоректно, і власник вручну
  підтримує таблицю відповідності у Wix)
- Підготувати базу для нового великого функціоналу — Школи інструктора
  з власним закритим доступом для студентів (лекції, відео, облік
  випускників)

## Поточний стан

- **Старий сайт:** Wix, `fitzone.com.ua`. Частина сторінок зроблена
  базовим конструктором Wix, частина — кастомним Velo/HTML-кодом
  (власник може надати код окремих сторінок за потреби)
- **Новий сайт:** Flask-застосунок (`app.py`), шаблони Jinja2 у
  `templates/`, статика в `static/`
- **Аналіз старого сайту** ведеться в `docs/pages/` — по одному опису
  на розділ, зі скріншотами, перш ніж переносити в код. Це навмисний
  крок "спочатку зафіксувати, що є, потім писати код"
- Задокументовано на разі 10 розділів: Головна, Тренажерний зал,
  Групові тренування, Реабілітація (нова сторінка, не копія старої),
  Масаж, Сауна, Солярій, Команда, Розклад, Прайс
- Є чернетка вимог по Школі інструктора (`docs/notes/` або
  `docs/pages/10-school-instructor/`) — вимоги зафіксовані, рішення по
  архітектурі ще не прийняті

## Обсяг

Повний перелік розділів і роутів — у `02-site-structure.md` (файл

  студентів за email

## Що НЕ переписуємо самі

- Мобільний застосунок **Fit Control** — сторонній, лишається як є,
  сайт тільки посилається на нього (Google Play / App Store)
- Платіжна система — інтеграція (запити до LiqPay), не власна
  розробка платіжного функціоналу

## Оновлення вимог (лог рішень)

- **Єдиний інбокс вхідних повідомлень.** Підтверджена нова вимога:
  адмінка отримує окремий розділ "Вхідні" — агрегатор повідомлень з
  Telegram, Viber та Instagram в одній стрічці, з можливістю
  відповісти клієнту напряму з адмінки, без прив'язки до внутрішньої
  бази клієнтів. Це свідоме розширення обсягу проєкту: раніше
  передбачалось, що ці канали лишаються "як є" (лише кнопки-посилання
  на сторінках Сауна/Реабілітація/Розклад тощо, самі кнопки нікуди не
  діваються). Тепер до цього додається власний Reception-модуль в
  адмінці. Деталі ролі й екранів — `06-admin.md`, розділ "Єдиний
  інбокс"; підсистема в загальній архітектурі — `03-architecture.md`.

## Рішення, які вже прийняті

- **СУБД: PostgreSQL** — тримається на сервері розробника застосунку
  (того ж, що робить Fit Control та іншу серверну частину)
- **Розклад** — повністю читається через API (як і зараз), логіку
  переносимо як є
- **Прайс** — на старому сайті ще не добудований до кінця, але дані
  йдуть з **того самого API, що й розклад** (не окреме API — усі
  потрібні поля вже там). Додатково — три власні таблиці власника в
  Wix: (1) таблиця фільтрів/назв для категорій "Масаж" і
  "Персональні", (2) таблиця тексту нижньої інформаційної плашки,
  (3) таблиця відображуваних назв абонементів. Деталі — `05-api.md`,
  після отримання опису API та експорту цих таблиць
- **Оплата** — інтеграцію (запити до платіжної системи) віддає
  розробник застосунку, сидить на тому ж сервері
