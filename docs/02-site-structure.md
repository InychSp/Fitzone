# 02. Карта сайту, роути та наскрізні блоки (Site Structure & Routes)

Документ описує глобальну структуру сторінок сайту Fitzone, карту
роутів (URL-адрес) для Flask-застосунку, а також наскрізні елементи
інтерфейсу (шапка, футер, модальні вікна), однакові для всіх сторінок.

> Цей документ замінює собою `sitemap.md` (там саме зараз стоїть
> позначка, що файл застарів) — уся карта роутів тепер тут, з
> виправленнями і посиланнями на реальні старі Wix-адреси.

---

## 1. Наскрізні блоки інтерфейсу (Global Layout Components)

Ці компоненти входять до базового шаблону (`base.html`) і рендеряться
на кожній сторінці сайту.

### 1.1. Шапка сайту (Header)

* **Логотип Fitzone** — клікабельний, веде на головну (`/`)
* **Головне меню:**
  * Головна (`/`)
  * Послуги ▾ (випадне меню):
    * Тренажерний зал (`/services/gym`)
    * Групові тренування (`/services/group-training`)
    * Реабілітація (`/services/rehabilitation`)
    * Масаж (`/services/massage`)
    * Сауна (`/services/sauna`)
    * Солярій (`/services/solarium`)
  * Команда (`/team`)
  * Розклад (`/schedule`)
  * Прайс (`/price`)
  * Школа інструктора ▾ (`/school`)
  * Блог (`/blog`)
* **Контакти** — телефон рецепції / кнопка запису

> 🟡 **Відкрите питання, не підтверджено ні в одному іншому
> документі:** чи потрібен перемикач мови на сайті (мультимовність)?
> Наразі всі сторінки й `pages/*.md` — одномовні (українська). Якщо
> мультимовність не потрібна — прибираємо цей пункт із шапки.

### 1.2. Футер сайту (Footer)

* **Блок 1:** лого + короткий опис клубу
* **Блок 2:** швидкі посилання — повтор основних розділів
* **Блок 3:** контакти й графік роботи (адреса, телефони рецепції) —
  ⚠️ конкретну адресу і графік потрібно уточнити з власником, у
  жодному з попередніх документів вона не фігурувала
* **Блок 4:** соцмережі й месенджери — Instagram, Telegram, Viber
* **Блок 5:** юридична інформація й оплата:
  * Публічна оферта (`/legal/terms`)
  * Політика конфіденційності (`/legal/privacy`)
  * Правила клубу (`/legal/rules`)
  * Іконки платіжних систем (LiqPay, Visa, Mastercard)
* Копірайт `© Fitzone {рік}. Усі права захищені.`

## 2. Карта роутів (Route Mapping)

### 2.1. Публічні сторінки

| Сторінка | Новий route | Шаблон Jinja2 | Джерело даних |
|---|---|---|---|
| Головна | `/` | `index.html` | Статичний контент + карусель тренерів (`team_members`, прев'ю) |
| Тренажерний зал | `/services/gym` | `pages/gym.html` | Статичний контент + карусель тренерів (`team_members`, категорія `тренажерний-зал`) + кнопки-посилання на `/price` (без прямого виклику API з цієї сторінки) |
| Групові тренування | `/services/group-training` | `pages/group_training.html` | `group_training_services` + `trainer_services` (для фільтра "Тренер") |
| Реабілітація | `/services/rehabilitation` | `pages/rehabilitation.html` | `team_members` (категорія `реабілітація`) + `price_private` конкретного тренера, показ по кнопці "Показати ціну" |
| Масаж | `/services/massage` | `pages/massage.html` | Статичні картки "Види масажу" + карусель тренерів (`team_members`, категорія `масажисти`) + кнопка-посилання на `/price?category=massage` (без прямого виклику API з цієї сторінки) |
| Сауна | `/services/sauna` | `pages/sauna.html` | Статичний опис видів сауни + **прайс вбудований прямо на сторінці** через API `servpost.php` (група `sauna`) |
| Солярій | `/services/solarium` | `pages/solarium.html` | Статичні таби з описом + **прайс вбудований прямо на сторінці** через API `servpost.php` (група `solarium`) |
| Команда | `/team` | `pages/team.html` | `team_members` + `trainer_categories` |
| Розклад | `/schedule` | `pages/schedule.html` | API `servpost.php` (розд. 1 `05-api.md`) + кеш `schedule_cache` |
| Прайс | `/price` | `pages/price.html` | API `servpost.php` (розд. 2–4 `05-api.md`) + 4 таблиці конфігу прайсу |
| Блог | `/blog` | `pages/blog.html` | TBD — джерело контенту блогу ще не обговорювалось окремо |
| Школа інструктора (публічна частина) | `/school` | `pages/school.html` | Статичний контент — опис напрямків навчання, педсклад |

> ⚠️ **Виправлено відносно попередньої версії файлу:** прибрав
> посилання на неіснуючу таблицю `services` — такої таблиці немає в
> `04-database.md`. Для залу/масажу/сауни/солярію джерела даних
> зведені за фактичним описом у `pages/*.md` і уточненням власника:
> зал і масаж — це карусель тренерів + просто кнопка-посилання на
> сторінку Прайс (сама сторінка прайс не запитується); сауна і
> солярій — прайс дійсно підвантажується і показується прямо на
> сторінці.

### 2.2. Юридичні сторінки

| Сторінка | Route | Опис |
|---|---|---|
| Публічна оферта | `/legal/terms` | Договір і умови послуг |
| Політика конфіденційності | `/legal/privacy` | Обробка персональних даних |
| Правила клубу | `/legal/rules` | Регламент відвідування |

### 2.3. Внутрішні AJAX-ендпоінти (НЕ публічний API)

> 🔴 **Виправлено — головна помилка попередньої версії файлу.**
> Розділ раніше називався "Внутрішні / API роути" і містив
> `/api/v1/schedule`, `/api/v1/price`, `/api/v1/payment/callback`.
> Це суперечило вже прийнятому рішенню в `03-architecture.md`:
> окремий публічний версійований REST-API нам не потрібен. Особливо
> проблемний був `/api/v1/payment/callback` — за `05-api.md` (розділ
> 6.5) банк шле колбек оплати **на сервер розробника застосунку**,
> а не до нас; такого ендпоінта на нашому боці взагалі не існує.
>
> Нижче — те, що реально потрібно: невеликі AJAX-ендпоінти для
> конкретної сторінки, без версійного префіксу `/api/v1`, що
> повертають дані лише для власного фронтенду.

| Route | Метод | Опис |
|---|---|---|
| `/price/cards` | GET | Підвантаження карток тарифів при зміні фільтра на Прайсі без перезавантаження сторінки (заміна протоколу `postMessage` між віджетами `#Filters`/`#Content` зі старого Wix — `05-api.md`, розд. 7.9) |
| `/schedule/week` | GET | Підвантаження тижня розкладу при навігації стрілками "вперед/назад" |

Вебхуки єдиного інбоксу месенджерів (нова підсистема, `03-architecture.md`
розд. 5) винесені в `06-admin.md` — це вхідні інтеграційні ендпоінти
конкретного модуля адмінки, а не частина публічного API сайту.

## 4. Глобальні модальні вікна (Modals)

### 4.1. Модалка оплати абонемента (`#payment-modal`)

> 🔴 **Виправлено — раніше тут був спрощений і невірний опис** ("форма
> Ім'я/Телефон/Email + вибір часу"), що суперечив детально
> задокументованому в `05-api.md` (розд. 7.9) реальному робочому
> флоу. **Джерело правди — `05-api.md`**, тут лише короткий переказ
> для орієнтації:

Викликається зі сторінки `/price` (кнопка "Оплатити" на картці
тарифу). Кроки:

1. **Телефон** — інпут + кнопка "Знайти клієнта" (без email і без
   вибору часу — це не форма запису, а пошук вже зареєстрованого
   клієнта клубу)
2. Завантаження, поки триває пошук
3. Результат пошуку:
   - не знайдено / помилка → назад на крок 1 з повідомленням
   - клієнт у чорному списку → "Оплата недоступна", лише кнопка
     "Закрити"
   - знайдено кілька людей на одному номері → радіо-список ПІБ
4. **Підтвердження** — ПІБ, зал ("ЗАЛ: FitZone"), назва абонемента,
   сума → "Так, оформити" / "Назад"
5. Редирект на LiqPay (`liqpay_checkout.php`)

Повна деталізація — `05-api.md`, розділи 6 і 7.9.

### 4.2. Модалка деталей тренера (`#trainer-modal`)

Викликається на `/team`, `/services/massage`, `/services/rehabilitation`.
Показує розширений опис, фото, кваліфікацію, Instagram; для
реабілітологів — додатково кнопку "Показати ціну" (`price_private`
конкретного тренера, `04-database.md`).

## 5. Редіректи зі старих Wix-адрес (SEO)

Нові адреси — чисті й людські (`/services/gym` замість
`/gym-levoberegniy`), але щоб не втратити позиції в пошуку і не
показувати відвідувачам, які прийшли за старим посиланням
(закладка, стара розсилка, індекс Google), помилку 404 — потрібні
**постійні (301) редіректи** зі старих реальних Wix-адрес на нові
роути. Реальні старі адреси беремо з `sitemap.md`/`pages/*.md`
(попередня версія цього файлу мала спрощені й невірні старі адреси —
`/gym`, `/rehabilitation`, `/schedule`, `/price`, `/team` замість
справжніх):

| Старий Wix-URL | Новий route | Статус-код |
|---|---|---|
| `/gym-levoberegniy` | `/services/gym` | 301 |
| `/poslugy` | `/services/group-training` | 301 |
| `/reability` | `/services/rehabilitation` | 301 |
| `/massage` | `/services/massage` | 301 |
| `/sauna` | `/services/sauna` | 301 |
| `/solarium` | `/services/solarium` | 301 |
| `/komandalev` | `/team` | 301 |
| `/rozkladfitzone` | `/schedule` | 301 |
| `/price-lev` | `/price` | 301 |
| `/blog-1` | `/blog` | 301 |
| `/grafik-potokov` | `/school` | 301 |
| `/distancionoeobuchenie` | `/school` | 301 |
| `/opisanie-prepodov` | `/school` | 301 |
| `/nashivipuskniki` | `/school` | 301 |

Реалізація — простий словник `OLD_TO_NEW_REDIRECTS` у Flask
(`app.py` або окремий blueprint), який на старті реєструє
`redirect(new_url, code=301)` для кожного старого шляху. Важливо саме
**301**, а не 302 — так пошукові системи переносять "вагу" сторінки
на нову адресу, а не індексують обидві.
