# 06. Адмін-панель (Admin Panel Specification)

Документ описує інтерфейс, систему ролей і модуль Школи інструктора
адміністративної панелі Fitzone (Flask, окремий захищений blueprint)
для управління тренерами, послугами, конфігуратором цін, доступом
студентів і єдиним інбоксом вхідних повідомлень.

---

## 1. Авторизація і ролі

* **Маршрут входу:** `/admin/login`
* **Механізм автентифікації:** сесійна авторизація на хешованих
  паролях (`werkzeug.security`), таблиця `admin_users` — `04-database.md`

### Матриця прав доступу

| Розділ адмінки | Роль Admin | Роль Reception |
|---|:---:|:---:|
| Команда (`/admin/team`) | ✅ | ⛔ |
| Послуги (`/admin/services`) | ✅ | ⛔ |
| Конфігуратор цін (`/admin/price-config`) | ✅ | ⛔ |
| Доступи студентів Школи (`/admin/students`) | ✅ | ⛔ |
| Єдиний інбокс (`/admin/inbox`) | ✅ | ✅ (основний і єдиний екран) |

---

## 2. Єдиний інбокс повідомлень (`/admin/inbox`)

> ✅ **Підтверджена вимога.** Раніше передбачалось лишити месенджери
> "як є" (лише кнопки-посилання на сторінках сайту) — власник свідомо
> розширив обсяг, додавши цей модуль. Зафіксовано в `01-project.md`
> (лог рішень) і `03-architecture.md` (підсистема 5).

Єдиний агрегатор вхідних повідомлень з Telegram, Viber та Instagram в
одній стрічці — без прив'язки до внутрішньої бази клієнтів клубу
(`spk`/`bsp` з `05-api.md` тут ні до чого, це геть окрема сутність).

* **Верхнє меню:** лише вкладка "Вхідні" і кнопка виходу (для ролі
  Reception — це взагалі єдиний доступний екран)
* **Ліва панель** — список діалогів, найновіші зверху:
  * бейдж каналу (Telegram / Viber / Instagram)
  * ім'я/нікнейм/телефон відправника
  * статус: Нове / В роботі / Оброблено (`ConversationStatus`,
    `04-database.md`)
* **Права панель** — вікно діалогу:
  * повний текст повідомлень (історія — `inbox_messages`)
  * поле відповіді, що йде напряму в месенджер клієнта через API
    відповідної платформи

### Технічна інтеграція (вебхуки)

| Route | Метод | Опис |
|---|---|---|
| `/admin/inbox/webhook/telegram` | POST | Вхідний вебхук Telegram Bot API |
| `/admin/inbox/webhook/viber` | POST | Вхідний вебхук Viber Bot API |
| `/admin/inbox/webhook/instagram` | POST | Вхідний вебхук Instagram Graph API |
| `/admin/inbox` | GET | Список діалогів (обидві ролі) |
| `/admin/inbox/<conversation_id>` | GET / POST | Перегляд і відповідь у діалозі |

> 🟡 Кожна платформа — окремий протокол інтеграції (у Instagram Graph
> API, зокрема, потрібен підключений Facebook Business-акаунт і
> проходження модерації Meta) — деталі підключення й потрібні
> API-ключі/токени виносимо в `09-deployment.md`, коли дійдемо до
> нього.

## 3. Управління командою (`/admin/team`)

* Перегляд, створення й редагування карток тренерів (`team_members`)
* Завантаження фото, вибір категорій (M2M `trainer_categories`),
  призначення кваліфікації (`Classic/PRO/PRO+/VIP/VIP+/Авторський`)
* Індивідуальна ціна занять (`price_private`) — потрібна для сторінки
  Реабілітація
* Прив'язка послуг, які веде тренер (M2M `trainer_services`) — форма
  множинного вибору з каталогу `group_training_services`
* Перемикач видимості на сайті (`is_published`) і сортування
  (`display_order`)

---

## 4. Управління послугами (`/admin/services`)

* Редагування каталогу групових тренувань (`group_training_services`)
* Категорія (Динамічне/Спокійне/Дитячі), тип абонемента, віковий
  опис (вільний текст), відео-огляд
* Той самий вибір тренерів, що й у картці тренера (одна M2M-таблиця
  `trainer_services`, редагується з обох боків)

## 5. Конфігуратор цін (`/admin/price-config`)

> ⚠️ Уніфіковано нейменування роута — раніше в цьому документі був
> `/admin/prices-config`, а в `02-site-structure.md` — `/admin/price-config`.
> Залишено **`/admin/price-config`** (однина, як і назви таблиць
> `price_*_config`).

Редагування 4 конфігураційних таблиць прайсу (`04-database.md`,
розд. 3): `price_groups_config`, `price_plans_config`,
`price_rules_config`, `price_names_config` — категорії, другий
фільтр, текст інформаційних плашок, override назв і порядку карток.

## 6. Школа інструктора: доступи студентів (`/admin/students`)

За описом власника: окремий екран для сторінки "Теорія" зі списком
email, кому надано доступ, і окремий екран для сторінки "Практика" зі
своїм списком email. В основі — одна таблиця `students`
(`04-database.md`, розд. 6) з двома прапорцями (`has_theory_access`,
`has_practice_access`), а в адмінці це подано як два фільтровані
списки:

* **Екран "Теорія":** список email з `has_theory_access = true`,
  форма додавання нового email до цього списку (окремо від практики)
* **Екран "Практика":** те саме для `has_practice_access`
* Один і той самий email може бути додано в обидва списки незалежно
* Статус доступу: Активний / Заблокований (`is_active`)

**Закритий розділ на сайті для студентів:**

| Route | Опис |
|---|---|
| `/school/login` | Вхід студента (за email) |
| `/school/theory` | Матеріали теорії — лише якщо `has_theory_access = true` |
| `/school/practice` | Матеріали практики — лише якщо `has_practice_access = true` |

> 🟡 **Відкриті питання (лишаються нерозв'язаними, не блокують
> схему даних):**
> - механізм входу студента — магічне посилання на email
>   (рекомендований дефолт, поля під нього вже є в `students`),
>   логін/пароль чи код на пошту — підтвердити з власником;
> - масове додавання email (імпорт списку) чи лише вручну по одному;
> - де зберігаються відео — власний хостинг, YouTube (приховані) чи
>   Vimeo;
> - зв'язок цього розділу з "Педагогічний склад" — це той самий
>   список тренерів, що й у Команді, чи окрема сутність.

## 8. Зведена схема маршрутів

| Route | Метод | Ролі | Опис |
|---|---|---|---|
| `/admin/login` | GET / POST | усі | Вхід в адмін-панель |
| `/admin/logout` | GET | усі | Вихід |
| `/admin/dashboard` | GET | Admin | Загальна панель |
| `/admin/inbox` | GET | Admin, Reception | Єдиний інбокс — список діалогів |
| `/admin/inbox/<id>` | GET / POST | Admin, Reception | Діалог і відповідь |
| `/admin/inbox/webhook/telegram` | POST | — (сервісний) | Вхідний вебхук Telegram |
| `/admin/inbox/webhook/viber` | POST | — (сервісний) | Вхідний вебхук Viber |
| `/admin/inbox/webhook/instagram` | POST | — (сервісний) | Вхідний вебхук Instagram |
| `/admin/team` | GET / POST | Admin | Управління тренерами |
| `/admin/team/<id>` | PUT / DELETE | Admin | Редагування / видалення тренера |
| `/admin/services` | GET / POST | Admin | Управління групами тренувань |
| `/admin/price-config` | GET / POST | Admin | Конфігуратор цін (4 таблиці) |
| `/admin/students` | GET / POST | Admin | Доступи студентів (Теорія/Практика) |
| `/school/login` | GET / POST | Студент | Вхід студента |
| `/school/theory` | GET | Студент з доступом | Матеріали теорії |
| `/school/practice` | GET | Студент з доступом | Матеріали практики |
| `/admin/system-status` | GET | Admin | Кеш, імпорт/експорт |
